A mock we can be held to.

This revision removes live blur, system-font substitution, browser-native switches, and unconstrained responsive sizing. It uses the Portal’s font files and a fixed Android dp canvas. Production Android work has not started.

Supported primitives

Geometry & surfaces

Rows, columns, fixed constraints, rounded rectangles, linear gradients, tints, scrims, image crops, and vector paths map directly to Compose. No Liquid Glass shader or API 31 blur is required.

Shared assets

Typography & icons

Roboto regular, medium, and bold were copied read-only from this Portal. The exact icon paths and reference photos ship with the mock. No Apple-only font, emoji, CDN, or font-provider dependency.

Mapped to existing code

Behavior & settings

All 22 current settings destinations remain accounted for. The ten existing domains remain the source of truth. New navigation, favorites, editing actions, and setup journeys require implementation after approval.

On-device proof pending

Final visual acceptance

Browser and Android text rasterization can differ. The installed Compose UI must be compared at 2160 × 1440 using the same sample content. Visible mismatches must be corrected; any required design deviation comes back for approval.

What is outside the visual target

Android’s keyboard, Wi-Fi settings, permissions, package installer, and third-party app screens are rendered by their owners. This mock shows the Immortal handoff, not a promise to restyle those external screens. Real albums, weather, and household controls vary with your content.

Git preservation is part of the brief

After design approval, first record the current state and preserve existing changes, then create a new codex/portal-plus-ipad-ux branch before any Android edits. Do not reset, clean, overwrite, or uninstall to obtain a clean baseline. The current app, settings, signing identity, and previous mocks stay recoverable.
