# Dead-code cleanup: 2026-11-20

Base: `main` 1.280 (versionCode 274, `47cc57c8`). Branch `dead-code`, five commits. Nothing
should behave differently.

## How unused code was found

1. **Symbols.** A scanner listed every `fun` / `val` / `var` / `class` / `object` declared in
   `app/src/main/java`, skipping overrides:
   - A private symbol counts as unused when its name appears nowhere else in its own file
     **and** nowhere else in the repo, so reflective test access is still caught
     (`RemoteRoutesNavigationTest` calls `runSteps` by name).
   - Any other symbol counts as unused when its name appears only once in the whole repo. The
     search covers `app/src` (main, debug, test, androidTest, res, assets with the remote/Fleet
     JS and HTML, manifest), the R8/ProGuard rules, `baseline-prof.txt`, the Gradle files,
     `provisioning/` (including `fleet.rs`) and `mocks/`.
   - Each pass was repeated until nothing new turned up, because removing one symbol can leave
     its helpers unused.
   - The only remaining matches for removed names are in `docs/` and in the `mocks/` design
     inventories (snapshots that are never executed).
2. **R8 cross-check.** R8 had already dropped all 149 removed symbols from the baseline
   performance build. Each one appears in that build's `usage.txt`, either by name or because
   R8 removed its whole file class (`HomeAppTilesKt`, `HomeHeaderStatusKt`,
   `HomeWeatherWidgetKt`, `TimeProgressKt`, `CalendarWidgetKt`). Constants are inlined at
   compile time, so they never reach the dex at all.
3. **Resources.** `./gradlew :app:lintDebug` flagged them as `UnusedResources`. A second scan
   found no `R.<type>.<name>`, `@type/name` or `parent=` reference. The app has no
   `getIdentifier` call, and no `assets.open` or `android_asset` path could reach the deleted
   asset folder.
4. **Dependencies.** I checked each dependency's imports, plus any reflective or runtime use.

## Verification

- After every commit, `:app:assemblePerformance` and `:app:testDebugUnitTest` passed: 7,423
  tests, 0 failures. The last commit's classes.dex is byte-identical to the APK checked on the
  device; only the `ui-tooling-preview.version` META-INF entry differs.
- On the Family device (Android 10), a local main-1.280 performance build (same build
  environment) was compared with the cleanup build. uiautomator bounds dumps covered Home
  (both widget pages), Apps, Tools, Settings, Control Center, Music, Calls and the screensaver
  test source (generated scenes), plus each Back. Results:
  - **18 dumps:** the same top activity and node count every time. The only differences were
    live data: the clock, temperatures, crypto prices and how long a Control Center door
    sensor had been open.
  - **Pixel diffs (Apps, Tools, Settings):** 0 differing pixels.
  - **Screensaver test source:** `PhotoFramePreviewActivity` was on top in both builds.
    uiautomator returns the Home hierarchy underneath it, which was identical too.
- The official 1.280 artifact shows a different Music screen because it is built with the
  YouTube OAuth client in its build properties. A local main build shows the same "not set up"
  screen as the cleanup build, so this is an environment difference, not a code change.
- Afterwards Family was put back on the official 1.280 (sha matches the release log).

## Left in place on purpose

| Symbol | Reason |
|---|---|
| `RemoteRoutes.runSteps` | Called reflectively by `RemoteRoutesNavigationTest` |
| `WelcomeConfig.setGreetingColor/ClockColor/DateColor/GreetingLetterSpacing`, `ImmortalSettings.setConstrainPageWidth`, `ScreensaverConfig.clearCalendarUrl`, `Weather.clearLocationCache` | Write persisted preference keys; kept so settings keys and migration paths stay intact |
| `Transit` (whole object incl. `savedStopId/savedStopName/saveStop`) | No caller and stripped by R8, but it owns persisted `stop_id`/`stop_name` keys. Removing a feature needs an owner decision |
| `ScreensaverConfig.FEEDS`, `feedLabel`, `FEED_*` | Feed ids are persisted setting values ("picsum", "met", …) |
| `media3-exoplayer-hls`, `slf4j-nop` | Loaded reflectively or at runtime (HLS camera stream; smbj logging binding) |
| `MusicReceiverClient.AndroidTransport/MainScheduler`, `CallLoopback`, BuildConfig-gated diagnostics | R8 strips them from the performance APK, but they are reached from tests, androidTest or debug-flag paths |
| Code used only by unit tests | Out of scope: removing it changes tests, not just dead code |
| `mocks/` inventory JSON naming removed functions | Design snapshots, not executed; left as historical records |
