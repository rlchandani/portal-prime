# HTTP request input buffering

FleetHttpServer read each HTTP header byte directly from SocketInputStream. Every browser asset, paired remote request and fleet request passed through that path. The connection input now uses one 16 KiB BufferedInputStream shared by readHead, Request body readers and draining. The four existing workers add at most 64 KiB of input buffers. Header/parser limits, one-request connection framing, LAN/authentication gates, timeouts, handler concurrency, response handling and upload paths are unchanged.

## Evidence

The actual private serve path is exercised with a socket fixture rather than a second parser implementation. The original ten tests produced one failure and nine passes: the 2,132-byte header fixture made 2,132 raw single-byte reads. The buffered version passed all ten initial tests with zero raw single-byte reads and at most two bulk reads for the same complete request. Two review-requested cases were then added to verify Content-Length with prefetched trailing bytes and drain/response/socket-close ordering. Final full Android gate: 1,930 tests across 225 suites, zero failures/errors/skips; all 12 focused wire cases pass. All 138 browser tests pass. Debug build passed. The first incremental signed artifact was rejected before device access: generated installer=false did not match stale compiled installer strings/target. One full compilation using -Pkotlin.incremental=false --no-build-cache --rerun-tasks cleared the unchanged artifact guard; the corrected signed candidate is archived. The exact internal cache dependency failure remains unproven. The two added coverage cases were re-reviewed and cleared. Both signed artifacts and complete profile/local admission checks passed. One Family Area trial completed two signed installs, exact installed APK and served core/controller/CSS checks, three Home → Apps → Home destinations, unchanged configuration/source, final Home readiness and inactive collector; no rollback. Family lease released. Complete profile inventory: 8,667 methods / 2,576 classes / 285 app methods / 75 app classes. Individual method compilation unproven. Kotlin documents the full-compilation option at https://kotlinlang.org/docs/gradle-compilation-and-caches.html#incremental-compilation.

The fixtures also cover adjacent UTF-8 JSON, a 100,003-byte binary upload, a capped text prefix followed by streaming, unread large bodies, one-byte fragments, a gated Expect: 100-continue exchange, OPTIONS, incomplete and oversized headers. One stream owns all prefetched body bytes. No Kotlin parser visibility or request metadata fields were changed. Static review found no production defect; its two coverage suggestions are included.

A read-only Family Area public-asset baseline used no credentials and no UI actions: six ordinary requests measured median 12.378 ms / maximum 14.039 ms; six interleaved requests with an extra 2,048-byte header measured median 32.532 ms / maximum 47.446 ms. Exact 19,089-byte core asset checksum was verified each time. These small Wi-Fi samples are observations, not a controlled device-latency benchmark. Post-deployment six ordinary requests: median 11.146 ms / maximum 16.842 ms; six padded requests: median 14.93 ms / maximum 16.764 ms. Ordinary maximum increased; no consistent tail-latency or causal device-wide gain is claimed. A real TCP GET withheld its 100,003-byte dummy body until exact 100 Continue, then verified the 19,089-byte response checksum; passed in 30.701 ms. HTTP probes used no credentials, UI actions, file uploads or settings mutations.
