# Home photo warm-cache publication

The active Home photo card initialized to null and looked up its in-memory snapshot inside the single bounded PhotoSourceWork worker. An occupied worker delayed a valid cached image; a full two-entry queue rejected the job and returned null despite the available image. The cache now seeds the photo state immediately, and cachedOrLoad checks the same immutable memory snapshot before submitting cold work. The original inner worker-side cache recheck is retained, avoiding duplicate decoding if another request populates the cache while this request waits.

Cache key, TTL, elapsed-time clock, source matching, bitmap dimensions, retry timer, decoder, transport ownership, queue capacity, cleanup and lifecycle policy are unchanged. Cancellation is checked before and after the memory lookup; misses use the unchanged load path. No settings, user configuration, UI layout or photo-source credentials change. The cache owns one display-sized bitmap and adds no retained entries.

## Evidence
