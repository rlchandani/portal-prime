## What the fixture misses

The production happy-path wire shapes agree: preflight is `GET /remote/settings?domain=screensaver&includeInactive=1`, response is `{"ok":true,"settings":{"domains":[...]}}`, and POST returns `{"ok":true,"applied":[...],"domain":{...}}`. The group validates each captured destination independently and requires every posted key in `applied`. No current Shuffle contract defect was demonstrated by source inspection.

| Fixture assumption | Actual Portal behavior and acceptance implication |
| --- | --- |
| Invalid patches fail HTTP 400 before any mutation. | The known-domain route returns **HTTP 200 / `ok:true`** with per-key `applied`, including `[]` for wholly rejected values. A mixed patch can apply valid keys. The group already checks missing acknowledgements and retains only missing keys for retry; these rendered tests do not exercise that branch. HTTP success alone is insufficient. |
| Three synthetic controls supply all metadata. | Real specs contribute visibility, tiers, sections, defaults and enum metadata; on-device navigation specs contribute no remote control. Actual `intervalSec` is `int`, min 5, max 600, step 5, `asText:true`. Ordinary disabled screensaver schema is master-only; inactive schema exposes registered hidden children without enabling them. The fixture also rejects ordinary scoped GETs that production supports. |
| In-memory state plus an acknowledgement establishes completion. | A successful POST runs the domain's real `onApplied` hook, including screensaver reaffirmation and notifications. The group confirms acknowledged key names, not fresh values. Repository completion refreshes only the still-owned, captured viewed room and invalidates other target caches; refresh failure does not revoke the ledger result. Living therefore needs an explicit fresh readback. |

The fixture correctly returns a visibility-filtered POST `domain` for disabled B. Production does the same: a successful hidden Shuffle write can return only `enabled` in that domain's controls. Do not interpret that omission as rejection or feed inactive preflight controls into the displayed settings.

It does **not** exercise the native group's missing-key failure display: the native numeric editor blocks this invalid input before sending.
